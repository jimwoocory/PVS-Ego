# Go 执行桥：本机只读隔离验收

2026-10-20。基线为 PVS-Ego `67fcac5` 当前工作区，原业务实现及授权链保留。本轮新增内容仅在本地，尚未提交或上传。

## 已完成范围

使用无第三方模块依赖的 Go 标准库实现 stdio JSONL 执行桥。现有 Node CLI、JavaScript SDK、Electron/Chromium 宿主程序保持原样；验证时新建自有宿主实例、空白 Profile 和本机合成页面，不连接既有账号会话。

结构：定向验收程序 → Go 桥 → 固定只读 SDK 工作程序 → 现有 Ego CLI/宿主。没有启动通用 HTTP 执行服务，也没有提供任意 JS、网址、模型、文件上传或平台提交操作。

- 只允许 `probe` 与 `observe`；未知字段和操作拒绝。任务时限 100–10000ms，最多 1 个活动任务、每会话最多 256 个任务 ID、每任务最多 64 个工作程序事件。
- 明确指定本机配置，固定 Node/CLI/SDK 内容 SHA；限定本仓库运行目录、专用 host 目录、宿主实例身份及随机 fixture 路径。正式端口拒绝，缺失或变化停止，无正式配置回退。
- 接受项目/周期/动作/contextHash 作为关联信息，原样绑定到回传事件。它们不是新的授权令牌；Go 桥不签发或取代 PVS 业务许可。
- 取消和超时先停止 SDK 工作进程并观察退出，再发唯一终态，附工作进程 PID/退出观察；终态后不继续回传该工作程序事件。stdin EOF 取消活动任务。无自动重试、自动重开宿主或重提。
- 取消只终止当前只读执行，不回滚已发生的浏览器行为，不代表取消已提交的平台任务。浏览器已打开的页面可保留到本轮专用宿主清理。
- 事件包括连接、页面绑定、定时真实 DOM 观察及任务生命周期，有单调序号和时间。不是完整原生 CDP 事件流、无损事件总线或持久重连补发。

## 失败及修正保留

1. 初次 Go 版本检查的遥测路径访问被拒绝；构建运行器明确设置 GOTELEMETRY=off、GOTOOLCHAIN=local、GOPROXY=off、GOSUMDB=off、GOENV=off，并将缓存/临时目录设在本轮目录。无模块下载。
2. 受限运行器 spawn EPERM，未开始实际构建；同范围正常运行器可以执行。所有尝试分别保留。
3. 首次实际套件为 4 PASS / 4 FAIL：SDK round-console 缓存导致事件等脚本结束才回传，取消/EOF 因此落后于成功终态；改用固定工作程序直接写 Node stdout，真实观察逐次回传。拒绝断言也改为等待各自明确拒绝结果，避免把其他任务旧拒绝算入。
4. 首次失败尝试的自有宿主退出码为 3221225477，底层原因未确认；测试包装器从强制 app.exit 改为原宿主正常 app.quit 流程，后续独立新实例退出 0。没有修改 Ego 源码或重启原用户宿主。
5. Node 子测试失败不会自动中断父测试余下语句，早期失败尝试误写了预退出 PASS 文件。原件保留并追加 FAIL 限定记录；最终程序检查全部子项、套件真实退出码及自有子进程退出后，才由运行器写 `final-acceptance.json`。旧的 `qualified-result.json` 不能单独作为通过证明。

## 续轮：任务生命周期与现有界面隔离接线

2026-10-20 续轮仍以本地 `67fcac5` 和上述未提交文件为基线；前述 8/8 为上一轮记录，不替代下面的新证据。

代码审阅确认：`AgentCycleService.advance()` 在能力运行期间保留仓库租约；原 `cancel()` 同样需要取得租约，无法取消活动能力。租约恢复只清理已退出进程，不能为了取消释放活动锁。

本轮增加可选的本机生命周期回调与进程内活动句柄。只有测试目录中的 `research.go-lifecycle-fixture` 被明确注入，默认工厂、能力注册目录、隔离守卫和 Go 的固定只读工作程序均未放开执行。

- 原确认、版本、contextHash 和幂等检查先于能力执行。stdio scope 只是关联信息。
- 同进程、同项目、同周期、同动作与上下文且匹配运行版本时，可以向当前本机只读动作发取消信号；持锁流程继续等待工作程序退出回执并独占保存终态。旧版本、跨项目及并发推进均拒绝。默认未注入的能力保持原取消限制。
- `get/list` 叠加当前进程的有界进度；最终执行状态随原动作保存，不建立第二个业务任务库。取消期间保持 RUNNING，显示等待退出；确认退出后周期为 CANCELLED、动作保留 FAILED 与本机 CANCELLED 详情。超时为 BLOCKED，阻止自动进入模型规划或重试。
- 现有工作台显示连接、观察次数、取消、超时及退出确认。推进请求不再阻塞页面对取消的操作；状态刷新由 5 秒改为 1 秒，使短时观察期间可见取消按钮。此变化只在当前隔离仓库构建，未部署到原服务。
- 进程内句柄不跨服务实例或重启恢复；其他进程持有的活动租约仍拒绝取消。失联或缺少退出回执时不能宣称已停止；没有远端回滚承诺。生产 Prisma 库的活动取消接线未运行。

最终唯一专项 `tests/go-ego-bridge-isolated.test.mjs`：**9 PASS / 0 FAIL，套件退出 0**（8 个子项加父项）。修改 TypeScript 后 build 退出 0。没有运行全量或其他定向套件。

本轮新子项通过原 HTTP 处理器、原 Agent 工作台和未改的隔离守卫运行：内存仓库、禁止调用模型的 runtime、全新专用 Ego Profile 与本机随机合成页面。Tabbit 原生点击实际推进连接、运行中取消和超时；刷新后终态仍在。3 次桥调用、1 次取消请求；取消前页面可见 5 次观察，终态记录 16 次；超时记录 14 次。差值来自页面刷新到点击之间继续发生的只读观察。浏览器脚本错误 0；取消或超时后不重试，幂等调用不新增桥请求。

最终记录 95 个桥事件，合成页面 6 次 GET。宿主、Go 桥、原业务门禁 fixture、界面 fixture 及套件均观察退出 0；界面 fixture 的 beforeExit 仅余 stdout/stderr 两个 PipeWrap。浏览器自建标签关闭、Tabbit 任务正常释放。

**证据分层：本机 Go/SDK/宿主、原服务授权行为、原 HTTP 与浏览器原生点击通过；截图视觉验收仍 BLOCKED。** Tabbit 在续轮的一个新实例上实际截图等待 30000ms 超时，后续最终轮未重复截图，没有合格截图或视觉验收 PASS。真实平台 E2E、正式数据库持久化取消、实际用户业务授权均不在通过范围。

失败原件全部保留：首个运行器 spawn EPERM；第一轮页面 5 秒刷新错过约 4 秒观察，实际为成功且没有取消；第二轮浏览器完成回执落盘晚于子进程状态检查；其后清理尝试仍因输入流和自有 HTTP 连接导致退出等待失败，不能算 PASS。最终改为浏览器收到响应并保存回执后，父进程发送清理确认，fixture 关闭自有 HTTP 连接及输入流；无强制写退出码或预退出 PASS。最终结果仅由套件及子进程实际退出检查后的 `final-acceptance.json` 确认。

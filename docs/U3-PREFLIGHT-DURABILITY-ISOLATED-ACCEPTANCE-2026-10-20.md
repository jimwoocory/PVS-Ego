# U3 发布准备占位、预检与原页续接隔离验收

2026-10-20。基线为当前 `67fcac5` 未提交工作区，未提交、推送或部署。

## 本轮补齐

### 同一成片不能换包重复准备

原检查点的版本比较只约束单个发布包。另一发布包可能在准备中、准备失败或进程中断后，对同一成片再次调用准备。

现在首个 PREPARING 检查点、成片 SHA 占位及 assembly 占位在同一个 Prisma 事务中创建，复用原 VersionedEntity 唯一索引，没有新数据库或迁移。两个实际进程、不同发布包竞争时只有一个能进入准备。事务失败时占位和检查点一起回滚，准备调用为零。

占位按项目隔离；本轮不同合成项目使用相同字节仍能各自准备。同一项目的原占位不随失败、过期或进程退出自动释放。既有历史检查点也阻止换包绕过，不将历史 BLOCKED 或 PREPARING 当作可以重新上传的证明。本轮不新增解除占位或自动重试入口。

### 接管与归还确认绑定最新状态

接管与续接服务、原 HTTP 路由及原预检界面现在共同传递并核对：

- `expectedAccountId`：原发布账号的强身份；
- `scopeHash`：本次发布范围；
- `revision`：最新检查点版本；
- 对应操作的独立确认布尔值。

缺字段、旧版本、错范围或错账号在接管/续接执行前拒绝。旧页面及旧调用方需要刷新并带上当前元数据，不能只发送“已确认”。提交仍使用原有独立确认链，归还控制不等于同意发布。

续接只核对原包、原页和当前状态；账号、文案、文档、连接或期限改变时停止，不自动填表、重新上传、重开页面或提交。

### 检查点与页面边界

检查点读取和追加除验证外层哈希，还核对 scopeHash、项目/包归属、binding 的 runtime/account，以及 READY 等阶段必须具有 binding。追加不得变更原 scope；首个检查点必须为 PREPARING。

因此，即使合成故障重新计算外层哈希，内部范围哈希、包归属或账号 binding 不匹配仍被拒绝。预检 HTTP 对该完整性故障明确显示“已停止，检查原记录，不重新上传或提交”，不使用通用“请重试”提示。

Ego 本机分阶段候选的配置入口另拒绝原服务保护端口及缺少显式端口的地址；本轮仅构建检查该配置改动，未启动实际 Ego 发布执行器。真实平台契约、编辑态、上传和作品证明没有因此被启用或宣称通过。

## 失败保留及限制

首个 Tabbit 准备程序在准备已完成后，用相对 URL 调用 Node HTTP 读取失败；立即只读核验原检查点，没有再次准备。原错误回执、后续接管/续接回执、HTTP 记录和最终计数保留。

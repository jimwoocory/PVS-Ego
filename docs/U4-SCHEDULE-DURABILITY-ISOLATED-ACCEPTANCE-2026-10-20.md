## U4 实现

- 计划数据库行和 JSON 同时核对项目、请求键、输入哈希、状态、revision、nextAt；次数、历史索引和父评论范围也受校验。保存时不允许改写原输入范围。
- 执行前及异步账号核对后检查租约 owner、revision、RUNNING 和有效期。过期或暂停的旧执行器不能继续写计划，也不能清除新执行器的租约。
- 指标和评论数据保存事务内再次核验计划租约并取得数据库写锁，使暂停/转移与保存串行。这个过程同时覆盖部分指标的版本存储、原始评论页归档和评论写入；不能仅凭保存前的回调绕过。
- 每次指标、顶层评论或楼中楼读取前，先持久化具体请求键、类型、原采集 ID/页数等读取意图。新协议标记为 operations-read-intent-v1。
- 重启后只从已保存的同项目、绑定、作品、账号、父评论及原分页设置中核对结果。完整指标按原 captureKey 接回，完整分页检查点按原请求键或采集 ID 接回；不重新建立任务或回到第一页。当前 tick 仍最多读取一页顶层评论及一页楼中楼。
- 读取已经开始但没有完整保存结果时保留 READ_OUTCOME_UNKNOWN 与原意图，不自动重读、清理或伪造成功。普通异常与明确的运行时失败分开：明确失败有界退避，最多三次；未知结果不作为普通重试处理。评论页和游标之间不完整的中断也不会据文件/评论存在直接推进游标。
- AUTH_REQUIRED/RISK_CONTROL 暂停，保留已保存页和预算。新增原能力入口 operations.schedule-resume，属于 HUMAN_DECISION；必须确认当前 revision、原 inputHash 和运营账号 UID，重新核对原绑定。不修改次数、间隔、时间窗、作品或账号，不立即触发采集；嵌套的人工阻断采集也只恢复原任务。范围错误、预算耗尽和截止时间已到不能借续接扩大计划。
- 旧 RUNNING 缺少意图协议时保持阻断，不猜测上次读取是否完成；旧 SCHEDULED 可在原范围内接入新意图协议。含旧检查点的暂停任务也不能用“暂停再续接”绕过这项限制。

结果仍保留 PARTIAL、UNKNOWN、未观察计数和父评论上限。走完可见游标或达到观察次数，不代表完整平台覆盖或持续观察。

## U5 实现与实际本地链路

复盘前核对保存指标和评论的原文哈希、数值/正文、作品、父关系与观察记录。原保存行被改动时停止，不新建复盘、不重新采集。冻结证据还必须匹配原 metricSnapshotIds/commentIds，采集范围不得重复，不能只重新计算外层哈希后采用无关快照。

专项使用 U4 实际保存到新库的部分指标、顶层评论、楼中楼及采集检查点，经原本地复盘方法生成待审方法假设。只有夹具明确确认采用后，原策略能力 strategy.generate 以 activate=false 生成候选；实际保存 CreativeBatch 和不可变 STRATEGY_INPUT 文件/Artifact，另一实际进程核对候选内容及输入回执 SHA/绑定。停用后下一候选不再含反馈回执，既有产品事实、创意批次和已选创意保持不变。

运营数据来自进程内固定响应，创意结果也是固定替身。合成采用动作不代表真人采用了待审真实建议，也不证明任何创作质量、因果或商业效果。

## 验收方式与范围

先运行 npm run build，再运行 npm run test:u4-schedule-durable。它只从仓库迁移新建空白 SQLite，使用实际 Prisma 和原隔离守卫。应用不能执行命令或连接外网；没有复制正式库、项目、账号或配置。

29 个子检查和父检查共 30 项，覆盖：

- 两个实际进程的相同请求、活跃租约竞争；过期转移后的旧写入和释放拒绝。
- 实际进程重启、原顶层/楼中楼 ID 与游标、提前 tick 不读取、次数终止和部分覆盖。
- 指标/评论读取途中暂停，以及回调后、事务前暂停时的拒写。
- 五个真实进程死亡点：初始检查点、指标读取中、指标已保存、顶层页已保存、楼中楼页已保存。
- 人工登录阻断及最新确认、明确错误三次退避、账号/绑定变化、途中截止、损坏行/哈希、旧意图协议、原采集缺失或跨项目。
- U5 保存证据到本地复盘、明确合成采用、原策略候选与输入回执持久化、另一进程核对、停用后排除、原选择保护，以及保存行和冻结 ID 错误阻断。

时间控制使用注入时钟，租约到期和截止通过推进时钟验证；进程死亡和 SQLite 事务是真实的。测试直接驱动原服务 tick，没有启动常驻五秒后台 worker，未进行长期驻留、真实平台调度、HTTP 或浏览器点击验收。读取错误返回不承诺免登录或免验证码。

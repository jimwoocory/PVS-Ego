## PR #1 Go 本体取消超时与 worker 续审

以 `a1ffdd3` 为本轮基线，审查 Go 主程序、固定工作程序，以及 Agent、运营计划、智能制作 worker 的推进和租约路径。

- **P1：继承管道可能阻止取消和超时收尾。** 原 Go 循环读完 stdout 才调用 Wait，后代进程继承 stdout 时读操作可以一直不返回；仅关闭 stdout 仍不能解除 stderr 复制等待。现在 context 取消/到期关闭手动读取的管道，WaitDelay 将剩余复制等待限制为 250ms，并在直接工作进程被回收后发出唯一终态。EOF 和输入超限走同一收尾路径。这不是进程树停止或远端动作回滚保证；回执仍明确 remoteActionsRolledBack=false。
- **P1：Go 原生协议未完整约束页面、会话和事件顺序。** 会话绑定现在必须与实际 page 的 Space/Target 一致；读取要求先出现且仅出现一次可信来源的可见性诊断，隐藏时拒绝截图；拒绝 done 后事件、blocked 后继续输出业务事件及不符合模式的 sample，限制全部输出行数和总字节。原有效控制权错误码保留。可见性仍只是宿主布局诊断，不能授予控制权。
- **P2：长期 worker 的启动恢复与定时推进可以重叠。** 原恢复在单次执行保护之外，慢恢复时 interval 可以先推进任务；恢复失败后也可能直接进入后续 tick。现在恢复与推进共用串行保护，失败在以后 tick 重试且当次不推进。SCOPED 每轮只检查原精确任务的死租约，覆盖启动之后失去执行进程的情况；停止后不再启动后续读取、恢复或阶段，DISABLED 不建立定时器或读取任务。活动中的一步不会被 stop 强制中断，当前活租约保护和业务确认门禁保持。
